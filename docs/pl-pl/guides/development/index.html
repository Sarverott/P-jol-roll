    Rozwój¶

    Jak zmienić kod. Jak zaproponować zmianę, zobacz WKŁAD.

    Kod¶

    Plik Co w nim jest?
    src/core/main.ts argumenty i polecenia. Sposób użycia jest napisany na jego szczycie
    src/core/apihandlers/eli.ts API: jego adres, kształty odpowiedzi, adresy kazdej czesci aktu
    src/core/resources/store.ts Gdzie są zapisane rzeczy i w jaki sposób..part, następnie zmienić nazwę)
    src/core/crawl.ts jeden uprzejmy spacer przez adresy API: własne imię, tempo, kolejka w pamięci
    src/core/methods/gather.ts index → wymienia → lata, następnie pliki aktów rok po roku; --since dla zmian
    src/core/methods/seal.ts sumy kontrolne zebranych plików: pisanie rekordów, sprawdzanie plików przeciwko nim
    src/core/methods/compile.ts tabele szczegółów i odniesienia z plików surowych
    src/core/parsing/text.ts markdown od HTML, z nagraniami, które wiążą oba
    src/core/apihandlers/sejm.ts inne źródło: procesy i wydruki Sejm
    src/core/apihandlers/saos.ts inne źródło: orzeczenia sądowe
    src/core/methods/checkup.ts przeglądarka odwiedzająca strony internetowe, z Crawlee PlaywrightCrawler i Camoufox
    src/core/resources/hub.ts porównanie i synchronizacja z Hugging Face, z @huggingface/hub

    Cztery zasady utrzymują go do odczytu:

    • Adresy i dane trzymaj się z dala od opiekunów. Kierownik w gather.ts mówi, co się dzieje; gdzie zapytać jest w eli.ts i gdzie pisać jest w store.ts.
    • Jedno polecenie, jeden plik. main.ts Czyta tylko argumenty i telefony.
    • Bez płaskiego celownika. Pliki znajdują się w katalogu ich rodzaju pod src/core/: apihandlers/ dla źródeł, methods/ dla tego co robią polecenia, parsing/ dla plików surowych w tekście, resources/ dla stron lokalnych i Hugging Face. Nowy rodzaj dostaje nowy katalog.
    • Typy i interfejsy na żywo src/core/vars/. Jeden na plik, types/<Name>.type.ts lub interfaces/<Name>.interface.ts, z domyślnym eksportem i bez katalogów wewnątrz. W index.ts każdego katalogu umieszcza je w nazwach, GatheringScope oraz HuggingfaceScope, i kod zabiera je stamtąd:
    import type { GatheringScope } from "../vars/interfaces/index.js";
import type { GatheringScope as GatheringTypes } from "../vars/types/index.js";

function trusted(act: GatheringScope.Act, part: GatheringTypes.Part) {}

    src/cli-command.js, src/cli-repl.js, src/desktopapp/, src/webgui/ oraz src/webserver/ są początkami innych sposobów do tego samego rdzenia. Nie są jeszcze podłączone do niczego.

    Zadania¶

    Zadanie Co to robi?
    task lint Biome: kłaczki i formatowanie, nic nie zmienia
    task format Biome z bezpiecznymi poprawkami
    task build TypeScript do dist/, stronie internetowej do dist/web
    task test badania raz
    task check (lub task verify) kłaczki, budowa i testy - takie same jak CI. Uruchom go przed zgłoszeniem pracy, jak zrobił
    task seal, compile, text praca nad zebranymi plikami, bez internetu: patrz przetwarzanie
    task github:repo, runs, issues, prs czytaj stan repozytorium na GitHub z gh

    Każdy katalog z procedurami ma swój własny Taskfile.yml (.husky, .github, resources), zawarte w korzeniu.

    Badania¶

    Vitest, in tests/Nigdy nie dotykają prawdziwego API, stron internetowych czy Hugging Face.

    Plik Co sprawdza
    eli.test.ts wybór czasopism i lat, adresów, ścieżek plików
    gather.test.ts całe spotkania przeciwko lokalnej kopii API: listy, zamówienie, limit, pomijanie tego, co istnieje, rekordy, struktura i inne teksty, zmiany od dnia; następnie tabele, markdown i sumy kontrolne wykonane z wyniku
    sources.test.ts Sejm i wyroki przeciwko lokalnym kopiom ich API
    checkup.test.ts jak adresy stron internetowych są wypełniane z aktu
    hub.test.ts Nazewnictwo repozytoriów, i że tylko to, co się różni jest przenoszone

    Test, który wymaga API uruchamia mały serwer i wskazuje kod na nim:

    process.env.ELI_API = `http://localhost:${port}`;
process.env.RESOURCES_DIR = join(work, "resources");
process.env.CRAWLEE_STORAGE_DIR = join(work, "storage");

    Należy je ustawić przed przywozem kodu, ponieważ eli.ts oraz store.ts Przeczytaj je raz.

    Dodawanie jeszcze jednego pliku na akt¶

    Na przykład struct, które API daje jako /acts/DU/2026/1/struct:

    1. src/core/apihandlers/eli.ts: dodaj nazwę PARTS i jedna linia do filesOf, z adresem, o który jest proszony i zakończeniem nazwy pliku. Jeśli plik nie istnieje dla każdego aktu, nie zwracaj nic za czyny bez niego.
    2. tests/gather.test.ts: niech lokalna kopia odpowiedzi API na nią.
    3. docs/guides/data.md, docs/guides/gathering.md i tabeli w AGENTS.md.

    gather.ts oraz seal.ts bez zmian: plik kończy się .json jest zapisany jako JSON, jeden koniec w .pdf To musi być PDF, a wszystko inne zostaje zatrzymane. Oto jak struct zostało dodane.

    Dodawanie strony internetowej do kontroli¶

    Jeden wpis resources/frontends.json. Czytaj stronę internetową robots.txt Po pierwsze i napisać, co to mówi title kiedy nie pozwala na pełzanie.

    Dodawanie źródła¶

    Kolejny API to jeszcze jeden plik z jego adresami, kształtami i gromadzeniem i komendą w main.ts; sejm.ts oraz saos.ts są przykładami. crawl.ts daje uprzejmy spacer, store.ts zapisywanie plików, oraz hub.ts Przeprowadzka. Jego katalogi są resources/<source>-dataset oraz resources/<source>-bucket. Zaproponować go najpierw z formularza "new source" wydania; kandydaci już przeglądane są w pomysły.

    Styl¶

    Biome decyduje: zakładki, podwójne cytaty, sortowane importowanie. package.json utrzymuje przestrzeń. .obsidian/ nie jest sprawdzany. Haczyk pre-commit uruchamia Biome na upozorowanych plikach .husky/Taskfile.yml.

    Komentarze są krótkie i mówią dlaczego. // NOTE: komentarze są zadania od opiekuna, z ANSWER: linie jako odpowiedzi; oba pozostają.
