    Od plików surowych do tabel i tekstów¶

    task seal                 # checksums for gathered files that have no record yet
task seal -- --check      # read every recorded file again, name the ones that differ
task compile              # tables: details and references of acts, a year in a file
task text                 # markdown from gathered HTML, with checksums
task text -- --pdf        # and from the PDFs of acts without HTML (poppler-utils)

    Żaden z nich nie pyta o nic w Internecie. Czytają resources/bucket/ i zapisać do resources/dataset/Każdy może być powtórzony w każdej chwili.

    Checksums: seal¶

    Kubełek na Hugging Face nie daje sumy kontrolnej pliku, więc projekt zachowuje swój własny. Jedna linia na plik dataset/files/<journal>/<year>.jsonl:

    {"path":"DU/1918/WDU19180010001.json","size":3578,"sha256":"0c1f2c7e...","url":"https://api.sejm.gov.pl/eli/acts/DU/1918/1","gatheredAt":"2026-10-13T13:25:12.282Z"}
    Pole Znaczenie
    path plik, wewnątrz wiadra
    size, sha256 pliku, który został napisany
    url skąd pochodzi
    gatheredAt kiedy

    Zbieracz pisze rekord w chwili, gdy plik wyląduje na dysku, zanim cokolwiek zostanie wysłane gdziekolwiek. task seal jest dla plików zebranych przed powstaniem rekordów: zapisuje brakujące rekordy, z czasem modyfikacji pliku jako gatheredAt.

    task seal -- --check odczytuje każdy zapisany plik, który jest tutaj i porównuje. Drukuje ścieżki, które się różnią i kończy się błędem, gdy są jakieś. Uruchom go po pociągnięciu wiadro do innej maszyny, lub przed wielkim pchnięciem.

    Gdy plik posiada kilka rekordów, ostatni jest bieżącym.

    Tables: compile¶

    Szczegóły i odniesienia znajdują się w wiadrze jako jeden mały plik na akt. Do czytania luzem są połączone razem, rok w pliku:

    Tabela Jedna linia to: Wykonane z
    dataset/details/<journal>/<year>.jsonl szczegóły jednego aktu, jak dał im API <address>.json
    dataset/references/<journal>/<year>.jsonl jeden związek między dwoma aktami pole references szczegóły

    Linia tabeli odniesień:

    {"from":"DU/1918/2","type":"Uchylenia wynikające z","to":"DU/1918/23","date":"1918-10-21"}
    Pole Znaczenie
    from ELI aktu, którego szczegóły nazywają remis
    type rodzaj krawata, z lists/reference_types.json
    to ELI innego aktu
    date, art obecny, gdy API daje im

    Wszystkie tabele odniesienia razem są wykresem prawa: który działa zmienia, uchyla lub wykonuje który. Pierwsze szesnaście lat Dziennik Ustaw daje 45,658 krawatów za 11,008 aktów.

    Czyny, których szczegóły nie zostały jeszcze zebrane, są pomijane. Stoły są napisane w całości na każdym biegu.

    Texts: text¶

    Każdy zebrany HTML staje się plikiem markdown, dataset/texts/<journal>/<year>/<address>.md, i linia w dataset/texts/<journal>/<year>.jsonl przyłącza go do źródła:

    {"ELI":"DU/1918/2","markdown":"texts/DU/1918/WDU19180020002.md","sha256_md":"a85ee287...","sha256_html":"1fd223bc...","url":"https://api.sejm.gov.pl/eli/acts/DU/1918/2/text.html"}
    Pole Znaczenie
    markdown plik markdown, wewnątrz zbioru danych
    sha256_md suma kontrolna markdown
    sha256_html suma kontrolna HTML została wykonana z
    url HTML u źródła

    HTML, którego suma kontrolna się nie zmieniła, nie jest ponownie przepuszczona.

    Jak wygląda markdown:

    # Ustawa z dnia 4 lutego 1918 r. o Radzie Stanu Królestwa Polskiego

## Treść ustawy

### Art. 1.

Rada Stanu Królestwa Polskiego z siedzibą w mieście stołecznem Warszawie składa się ze 110 członków, a mianowicie:

a) 12 członków wirylistów,

    Artykuły, ustępy (§) i rozdziały są nagłówkami. Punkty i litery otwierają własną linię. Skrypty i przyciski czytnika Sejm są usuwane.

    Pamiętaj! markdown było rozpatrywane tylko w aktach od 1918 do 1933. Nowsze akty mogą używać HTML ten parser nie spełnia, a tabele nie są zamieniane na markdown tabel. Przeczytaj kilka nowych przed zaufaniem go hurtowo.

    Tylko HTML jest rozpatrywane: 39,110 z 164,638 aktów ma to, wszystko w Dziennik Ustaw. Pozostałe trzy czwarte mają tylko PDF i nie mają jeszcze markdown.

    Porządek obrad¶

    gather ──► seal (once, for old files) ──► compile ──► text ──► resources:push

    Teksty PDF¶

    task text -- --pdf daje markdown do działań, które mają tylko PDF. Warstwa tekstowa jest odczytywana przez pdftotext Poppler (scripts/install.sh Instalacje poppler-utils), która następuje po dwóch kolumnach strony dziennika. Linie stają się paragrafami, słowo wycięte na końcu linii jest przyklejone do tyłu, i Art. 1., § 1. oraz Rozdział 1 stają się pozycjami, jak w markdown z HTML. Cztery PDF są odczytywane na raz (--parallel); rok pięciu aktów zajmuje kilka sekund.

    Większość PDF przed 2000 są skany, że Adobe 's Paper Capture dał warstwę uznanego tekstu. Tekst ten jest zachowany tak jak jest, z jego błędami: nic nie jest poprawiane przez zgadywanie. Płyta nazywa producenta PDF, więc czytelnik może odróżnić te teksty od siebie:

    {"ELI":"DU/1953/228","markdown":"texts/DU/1953/WDU19530460228.md","sha256_md":"...","from":"pdf","sha256_pdf":"...","producer":"Adobe Acrobat 9.0 Paper Capture Plug-in","url":"https://api.sejm.gov.pl/eli/acts/DU/1953/228/text.pdf"}

    A PDF bez warstwy tekstowej (mniej niż 40 liter na wszystkich stronach, około jeden na sto) otrzymuje nr markdown; jest nazywany w dataset/texts/<journal>/<year>.scans.jsonl i czeka na OCR. Kiedy akt dostaje HTML później, markdown jest z HTML ponownie.

    Bez --pdf, task text zachowuje teksty sporządzone z PDF w takim stanie, w jakim są.

    Czytelnicy mówią, które teksty są: akt w api ma text.from (html lub pdf) z producentem i adres źródła, odpowiedź /api/acts/<journal>/<year>/<pos>/text posiada nagłówek X-Text-From, narzędzie MCP act_text otwiera taki tekst z wierszem o nazwie PDF, a przeglądarka umieszcza notatkę nad nim.

    Mapa całego prawa: map¶

    task map                        # every preset into dataset/map/
task map -- statutes-in-force   # one

    Wszystkie 165 tysięcy aktów z 750 tysiącami krawatów jest zbyt wiele dla strony, więc preset bierze część z nich, z więzami z jego aktów dataset/references/:

    Preset Akty Krawaty (2026- 11- 22)
    statutes-in-force Obowiązujące statuty (ustawy) 2,848 / 2,234
    statutes każdy statut od 1918 9,985 / 71,489
    in-force wszystkie obowiązujące akty 20,484 / 11,953
    statutes-in-force-by-meaning Obowiązujące statuty mające wektor (task embed), każdy związany z 5 najbliższym przez znaczenie zamiast więzów źródła tak wielu jak mają wektory

    ForceAtlas2 umieszcza je raz, tutaj (około minuty dla wszystkich trzech), więc przeglądarka tylko rysuje: zakładka "map of the whole law" przeglądarki pokazuje je z sigma.js, /api/map/<preset> daje im. Biegnij task compile Po pierwsze, więzy są świeże. Pliki idą do Hugging Face z zestawem danych, więc demo może je pokazać.

    Szukaj co roku: search:index¶

    task init                                         # once: resources/secrets/typesense_api_key
docker compose --profile search up -d typesense   # Typesense 30.2 on 127.0.0.1:8108
task search:index                                 # titles, types, statuses, keywords
task search:index -- --texts                      # and the first 2000 characters of each text

    Każdy akt idzie do kolekcji acts (zastąpiono już akt prawny). Tytuły, słowa kluczowe i teksty są tokenizowane jako polskie. api odpowiedzi /api/search?q=...&type=&status=&journal=&page= z aktami, zaznaczone słowa ich tekstów i liczy na typ, status i dziennik. Przeglądarka pokazuje pole "every year", kiedy wyszukiwanie odpowiada. Bez Typesense, /api/search odpowiada 503 i mówi, jak go uruchomić, i nic innego się nie zmienia. Wszystkie 165 tysięcy aktów zajmuje 10 sekund; z tekstami 20 sekund i około 450 MB pamięci w serwisie.

    Wektory tekstów: embed¶

    ollama serve &              # or: docker compose --profile llms up -d llms-ollama
ollama pull bge-m3          # once, about 1.2 GB
task embed                  # every text; task embed -- 2026 for one year

    Każdy akt z markdown otrzymuje jeden wektor: jego tytuł i pierwsze 2000 znaków tekstu, podane do lokalnego modelu wielojęzycznego przez Ollama (EMBED_MODEL, bge- m3 domyślnie: 1024 numerów, polski wśród jego języków). Są poza tekstami. dataset/embeddings/<model>/<journal>/<year>.parquet (ELI, sha256_md, vector), oraz model.json mówi jak zostały stworzone. Akt, którego markdown nie zmieniło się, zachowuje swój wektor, więc bieg powtarza się, aby wziąć to, co nowe.

    DU 2020 (2453 aktów) zajęło 1 minut 46 sekund na GeForce RTX {10} i 4 MB. Prawo zajęłoby dwie godziny i 670 MB.

    Szukaj w znaczeniu¶

    Z wektorami wykonanymi, task search:index Umieszcza je również w Typesense (istniejąca kolekcja zdobywa pole bez tworzenia na nowo). Poszukiwanie każdego roku z meaning=1 zamienia pytanie w wektor przez ten sam model Ollamy, a Typesense szeregi działa słowami i znaczeniem razem. Pytanie w języku angielskim znajduje polskie akty: "protection of children against violence at school" znalazła akty Ministra Edukacji na temat bezpieczeństwa w szkołach, gdzie same słowa znalazły jeden akt. Bez Ollamy, poszukiwania mówią meaning: false I działa tylko słowami. Przeglądarka pokazuje pole "by meaning, in any language" tylko wtedy, gdy host może to zrobić.
