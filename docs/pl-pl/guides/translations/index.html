    Tłumaczenia¶

    Pomysł właściciela (Q15, zmiana fazy 12): strony nie są przepisywane nazwami tekstów i ładowarek. Ich węzły tekstowe są odnalezione, podłączone do SHA-256 tego, co mówią, a ich zawartość jest zastąpiona pakietem językowym. Faza 16 sprawdziła to najpierw, w src/i18n/ z tests/i18n.test.tsTa strona mówi, co wyszło.

    Jak to działa?¶

    "115 acts"  -> normalized, numbers as holes -> "{0} acts" -> SHA-256 -> 6f1c...e2
pack PL-PL: "6f1c...e2": { "one": "{0} akt", "few": "{0} akty", "many": "{0} aktów" }
            -> "115 aktów"
    • src/i18n/sha256.ts: SHA-256, synchroniczny, taki sam w przeglądarce, w węźle i w terminalu (sprawdzony pod kątem własnego węzła).
    • src/i18n/hooks.ts: hookOf(text), translate(pack, text)oraz t(pack, text) dla terminala: tekst opakowania, lub angielski, gdy opakowanie nie ma żadnego. Liczba w tekście jest otworem, więc "3 acts" i "115 acts" są jednym wpisem; wpis może zawierać liczby mnogiej w jego języku (Intl.PluralRules), wybrany przez pierwszy numer.
    • src/i18n/dom.ts: collect(root) daje każdy haczyk strony ze swoim angielskim szablonem (tak tworzy się domyślne opakowanie), apply(root, pack) kładzie opakowanie na stronie, i apply(root, undefined) oddaje angielski, który jest zapamiętany na węzeł. follow(root, pack) trzyma paczkę na temat tego, co framework daje później.

    Co jest przetłumaczone: co jest oznaczone¶

    Od fazy 21 strona nazywa jaki jest jej interfejs, według klas; nic innego nie jest dotknięte:

    Klasa Przetłumaczone
    i18n-texts-slot każdy tekst pod elementem i czytelne atrybuty tego, co jest pod nim
    i18n-texts-placeholder do placeholder tego elementu
    i18n-texts-title / i18n-texts-alt / i18n-texts-label jego title / alt / aria-label

    Wewnątrz gniazda, dane pozostają pod translate="no" i kod jest pominięty. Wprowadzenie jest jednym szczeliną (jej <main>), przeglądarka oznacza swoje części jeden po drugim, a dokumentacja jest oznaczona jako jedno gniazdo przez jej konstruktora.

    Co działa¶

    Kontrola Jak
    węzły tekstowe i atrybuty czytane przez ludzi (placeholder, title, aria-label, alt) strona w linkedom
    liczba i liczba mnoga (1 akt, 3 akty, 115 aktów) t() i strona
    tylko to, co jest oznaczone przez klasy powyżej; wewnątrz niego dane nigdy nie są tłumaczone: tytuły i teksty aktów znajdują się pod translate="no", atrybut HTML ma do niego; code oraz pre są również pomijane strona
    powrót do angielskiego, lub do innego języka, bez przeładowania strona
    co Vue renders później: węzeł tekstowy napisany ponownie posiada angielski, obserwator tłumaczy go ponownie; angielski zapamiętany jest upuszczony jsdom, jako przeglądarka
    jedno opakowanie dla każdego interfejsu: ten sam hak na stronie, wyrzutnia i CLI t() Bierze proste struny

    Vue łata węzeł tekstowy poprzez napisanie jego nodeValue tylko wtedy, gdy jego własny wirtualny tekst się zmienia i nigdy nie czyta DOM powrotem. Przetłumaczony węzeł pozostaje więc przetłumaczony do czasu, aż Vue napisze go ponownie, a następnie obserwator przetłumaczy go ponownie. Strona i ramy nie walczą.

    Co nie, i co się z tym stało¶

    • Zdanie skrócone przez markup (" PDF u źródła jest tekst ") daje fragmenty, każdy hakowany sam. Porządek słowa różni się między językami, więc fragmenty źle tłumaczyć. Takie zdania otrzymują swoje własne krótkie sformułowania lub element oznaczony jako jedna jednostka później.
    • Ten sam angielski, dwa znaczenia ("status" jako kolumna i jako stan) to jeden haczyk. Kiedy to ma znaczenie, element dostaje data-i18n-context, który soli hak (nie jest jeszcze potrzebny).
    • Zmiana angielskiego sieroty jego tłumaczeniePonieważ hak się zmienia. Pakiet zachowuje angielski każdego wpisu, więc skrypt, który tworzy pakiety znajduje sieroty i tłumaczy nowy angielski ponownie; stare wpisy są wycofywane.
    • Wyszukiwarki nie widzą tłumaczenia w przeglądarce. Wprowadzenie i dokumentacja są zatem tłumaczone podczas budowy strony internetowej, przez te same apply() nad budową HTML, do /<language>/ kopie. Przeglądarka jest tłumaczona w przeglądarce.
    • Angielskie błyski Zanim przybędzie stado. Pakiet jest załadowany przed zamontowaniem przeglądarki.

    Pomysł trzyma się, bez tekstów wymienionych w kodzie: strony pozostają w formie pisemnej, interfejs jest oznaczony klasami i danymi standardowym atrybutem, a jedna mała biblioteka obsługuje przeglądarkę i terminal.

    Pakiety językowe¶

    resources/locales/ posiada plik JSON na język, wymienione w resources/locales/.index.json z EN- US domyślnie. Od fazy 28 jest git submodule: pakiety żyć w ich własnym gist (0b86ecd07d55426754759bdff{87}d4), źródło projektu czyta - świeży klon bierze go przez git submodule update --init resources/locales (task i18n:pull), oraz task init Mówi, kiedy zaginął.

    Opakowanie Wykonane przez
    EN-US.json task i18n:collect: wbudowane wprowadzenie i przeglądarka otwarta w przeglądarce bez głowy, ich własny runtime zbiera każdy tekst z hakiem
    PL-PL.json, UK-UA.json, DE-DE.json task i18n:translate: argostranslate (silnik LibreTranslate), modele pobrane raz 
    task web:build && npm run --prefix webpage build    # both pages built
task i18n:collect                                   # their English -> EN-US.json
task i18n:translate                                 # what the other packs miss
task i18n:translate -- PL-PL --again                # one pack anew (not its reviewed entries)
task i18n:publish -- "the texts of phase 28"        # committed in the gist, pushed, the submodule staged

    Paczka zmieniona tutaj (zebrane, przetłumaczone lub zweryfikowane przez osobę) dociera do wszystkich tylko po task i18n:publish: gist otrzymuje commit, a to repozytorium nowego commit podmodułu z następnym krokiem. Strumienie pracy, które budują, biorą pakiety przez git submodule update --init resources/locales.

    • Tekst z liczbą jest tłumaczony raz na liczbę mnogą języka, z liczbą, która przyjmuje (plural w indeksie: 1, kilka 3, wiele 5), a liczba staje się ponownie otwór.
    • Nazwa keep z indeksu (Dziennik Ustaw, Sejm, SAOS, P_JOL_ROLL...) nigdy nie są tłumaczone: stoją jako liczby, podczas gdy model działa, ponieważ litery są tłumaczone przez niektóre modele i liczby nigdy nie robią.
    • Tłumaczenie maszynowe popełnia błędy ("Bucket" stał się "Bukiet"). Osoba naprawia wpis w opakowaniu i wymienia swój hak w reviewedSkrypt nigdy nie nadpisuje recenzowanego wpisu i nigdy go nie upuszcza.
    • Język jest dodawany przez linię w indeksie (z jego argos pary) oraz task i18n:translate.

    Widz i wprowadzenie wziąć opakowanie ?lang=PL-PL, inny ostatni wybór, inne języki przeglądarki, inne angielski. Ładują tylko to opakowanie i kładą je na stronie, zanim się pokaże, a przełącznik w nagłówku zmienia je bez przeładowania.

    Dokumentacja jest tłumaczona przy budowie strony internetowej (scripts/devops/pages/build.sh działa src/devtools/docs-i18n.ts): budowana strona MkDocs jest kopiowana do site/docs/pl-pl/, uk-ua/ oraz de-de/, i każde opakowanie jest umieszczone na przewodnikach, glosariusz i strony głównej przez te same apply() przeglądarka używa. Zmiennokształtny i devlog pozostają w języku angielskim w każdej kopii, ponieważ zachowują słowa właściciela słowo w słowo. Każda strona otrzymuje listę języków w nagłówku, wskazując na tę samą stronę w każdej kopii. Read the Docs buduje tylko Anglików.

    Identifiers are never translated: a text that is one path or name (datasets/Sarverott/polish_national_law_docs) nie ma haka, a jeden wewnątrz zdania (resources/.map.json, SHA-256, v0.11.0) stoi jako liczba podczas gdy model działa, jak nazwy keep.

    Terminal¶

    Wyrzutnia (goła task), jego REPL i listy zadań mówią językiem terminala: P_JOL_ROLL_LANG=PL-PL task, inaczej LANG (pl_PL.UTF-8 daje PL- PL), inaczej angielski. Opisy zadań są podręcznikiem CLI, więc są one również tłumaczone.

    W kodzie tekst jest napisany raz, w języku angielskim, poprzez tr() (src/i18n/terminal.ts):

    tr("task {name} ended with {code}", { name, code })

    Angielski jest hakiem, jak na stronach. Nazwy miejsc w aparatach są wypełnione po opakowaniu, więc tłumaczenie umieszcza je tam, gdzie chce ich język. Podczas gdy model działa one w postaci liczb, jak cytowane polecenia ("list", "gather -- 2026"), więc żadne nie jest przetłumaczone. task i18n:collect znajduje każdy tr("...") z src/ i opis każdego zadania. Testy prowadzone w języku angielskim cokolwiek LANG maszyna ma (vitest.config.ts).
