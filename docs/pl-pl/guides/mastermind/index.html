    Magister prawa¶

    Pierwszy głos mistrza prawa (faza 30; plan właściciela w Q18): pytanie w słowach, na które odpowiedział model, który odczytuje akty za pomocą własnych narzędzi projektu MCP i cytuje każdy akt, na którym opiera się ELI. Nieformalne porady prawne: a diabelski adwokat każdy może sobie pozwolić.

    Jak to odpowiada¶

    1. Najbliższe akty. Pytanie staje się wektorem modelu, który stworzył wektory task embed (bge- m3) i narzędzie MCP search_meaning porównuje go z wektorem każdego aktu każdego roku.
    2. Ich smsy. Teksty najbliższych trzech (act_text) są czytane i przekazywane modelowi z pytaniem.
    3. Rounds. Model może wywołać dowolne narzędzie - act, act_text, search_acts, search_meaning-... przez maksymalnie sześć rund, a potem odpowiada.
    4. Cytaty sprawdzone. Każdy [DU/<year>/<position>] odpowiedź jest oznaczona read gdy model otworzył ten akt za pomocą narzędzia, oraz nieprzeczytane kiedy nazwał go z pamięci.

    Na tej maszynie: gospodarza Ollama¶

    Rozwój wykorzystuje Ollama gospodarza (http://127.0.0.1:11434) i jego GPU, deepseek-r1:8b oraz bge-m3 wciągnięty do niego:

    task mastermind:ask -- "Kto płaci podatek dochodowy od osób fizycznych?"
task mastermind:ask -- --json "..."        # with the reasoning and the tools it called
MASTERMIND_URL=http://127.0.0.1:11434 task serve
curl -G http://127.0.0.1:8080/api/ask --data-urlencode "question=..."

    Na innej maszynie: komponować¶

    Profil mastermind przynosi wszystko jako pojemniki: llms-ollama, llms-models (ciągnie modele raz, a następnie kończy), i mastermind - obraz webapp- server z zestawem mastermind, obsługującym /api/ask, /mcp i przeglądarka na 127.0.0.1:8081.

    task resources:pull -- dataset             # the acts and their vectors (dataset/embeddings/)
task mastermind:up                         # the GPU given to Ollama when nvidia-smi answers
docker compose logs -f llms-models         # the first start downloads about 6 GB
curl -G http://127.0.0.1:8081/api/ask --data-urlencode "question=..."
task mastermind:down

    Ręcznie: docker compose --profile mastermind up -doraz -f compose.yaml -f resources/services/gpu.yaml przed --profile dla kart NVIDIA (potrzebny jest zestaw do pakowania NVIDIA).

    The advanced strategy: a deepseek hosted by Hugging Face¶

    The owner's plan (Q18, phase 34): small models on the host first, the hard questions to a large deepseek hosted by Hugging Face. src/mastermind/strategy.ts:

    • --escalate: the usual model answers first; its answer goes on when it is weak - it says nothing, cites no act, or cites an act it never opened. The large one, deepseek-ai/DeepSeek-R1-0528 through Inference Providers (https://router.huggingface.co/v1; novita, deepinfra and featherless-ai serve it), gets the small one's answer to check, never to trust, and reads the acts itself through the same MCP tools.
    • --hard: straight to it.
    task mastermind:ask -- --escalate "Czy mogę odliczyć ulgę na dziecko po rozwodzie?"
task mastermind:ask -- --hard "..."
curl -G http://127.0.0.1:8080/api/ask --data-urlencode "question=..." -d escalate=1

    Here it is paid by HF_TOKEN z .env - the owner's own, so only a question the owner asks spends it; on the space by the signed-in visitor's token. The chat shows a switch a hard question when the host can pay for it (hard z /api/ask/about), and folds what the smaller model said first. The large one's conversation is kept with escalated: the small model, why its answer went on, what it said and where that is kept.

    Zmienna Domyślne Co to jest?
    HARD_MODEL deepseek-ai/DeepSeek-R1-0528 the model of hard questions
    HARD_URL https://router.huggingface.co/v1 jego OpenAI- like api
    HARD_KEY HF_TOKEN the token it is paid by

    Not yet seen answering for real: Inference Providers refuse the owner's token with 402 until it has credits (phase 32); it is tested against a stand-in of them.

    The Python stack¶

    The models and the simulations have a stack of their own (phase 34): stacks/python/, a uv project reading the law through the same MCP tools (Law) and asking the mastermind through /api/ask (Mastermind). task python:check, task python:law -- nearest "obowiązek szkolny".

    The executive agent¶

    Not a chat but a task (phase 33): a small qwen does what a person gives it, reading the law through the MCP tools, and writes what it is asked for into resources/agent/ - the only place it can write; it runs no command and fetches no page.

    task agent -- "Przeczytaj dekret DU/1919/147 i zapisz w pliku obowiazek-szkolny-1919.md streszczenie"
task agent:container -- "..."     # the same in the agents' shell, with Ollama of the profile llms

    Its first real task, on this machine: it read the school decree of 1919 and wrote resources/agent/obowiazek-szkolny-1919.md - school age from 7, seven years of school, to 14 - citing the articles, the act marked read. Every run is kept as a conversation (resources/conversations/qwen/...).

    Two engines (AGENT_ENGINE):

    • own (the default): the mastermind's rounds with the MCP tools given directly, and one tool of its own, write_note (a bare file name, markdown, never outside resources/agent/); its instructions are resources/configs/mastermind/executive.md.
    • opencode: opencode 2 as its host, as planned, from resources/configs/agentic-shell/opencode/ - its own config and data directories (resources/.containerdatavol/agent/), so neither the person's opencode settings nor sessions are touched, --standalone, a model of its own with a 24k context. Not yet reliable: opencode 2 hands an MCP server's tools over through Code Mode, and in some runs it does not find the server's namespace (Unknown tool 'p-jol-roll.act_text').
    Zmienna Domyślne Co to jest?
    AGENT_MODEL qwen3:8b the model
    AGENT_OLLAMA_URL http://127.0.0.1:11434/v1 its Ollama (http://llms-ollama:11434/v1 in the shell)
    AGENT_ENGINE own own lub opencode
    AGENT_ROUNDS, AGENT_CONTEXT 8, 24576 rounds of tools (own); context of its model (opencode)

    Ollama na własną rękę¶

    Modele są duże i liczne, więc Ollama tej maszyny utrzymuje je na napędzie własnym: OLLAMA_MODELS w .env (sama zmienna Ollama czyta) nadaje katalogowi nazwę.

    task ollama:where        # where they are read from, and how many are there
task ollama:serve        # the first start copies ~/.ollama/models there, then serves from there
task ollama:copy         # the copy again: only what is missing, then checked

    Stary katalog nigdy nie jest usuwany przez nich. Stop Ollama, który działa pierwszy (ss -ltnp | grep 11434 Pokazuje to). Dysk, którego root należy do roota, potrzebuje swojego katalogu stworzonego raz: task ollama:serve mówi sudo line.

    Rozmowy się utrzymywały.¶

    Każde pytanie jest trzymane ze wszystkim, co mówi, więc modele i rodziny można porównać:

    resources/conversations/<family>/<instance>/<UNIXUSAT>-<the question's first words>.json
resources/conversations/deepseek/deepseek-r1-8b/1795498362594-czym-byla-rada-stanu-w-1918-roku.json

    Rodzina pochodzi z resources/configs/mastermind/families.yaml (modele jednej rodziny działają jako jeden zespół: gemma4, translategemma, embeddinggemma, shieldgemma... są wszystkie gemma); przykładem jest model o jego wielkości. W aktach znajduje się pytanie, odpowiedź, rozumowanie, cytowane akty, wezwane narzędzia, jak długo trwało i cała wymiana - przedstawione teksty i na co odpowiedziały narzędzia. Katalog jest lokalną stroną ich własnego zbioru danych, Apokryf/Consiliariis-Polonicum-Lex (conversations z resources/.map.json): task resources:push -- conversations wysyła to, co nowe, ruch człowieka; git zatrzymuje tylko swoją kartę. MASTERMIND_KEEP=0 Nic nie zatrzymuje. W kompozycji jest to jeden katalog, który pisze mastermind.

    Rodziny jako zespoły¶

    resources/configs/mastermind/families.yaml nazwy rodzin i ich zespołów: jeden model odpowiedzi, jeden nazywa narzędzia w rundach, jeden zamienia odpowiedź w innym języku do pytania, jeden strażnik (jego werdykt zachował, nic nie powstrzymuje). Model jest dawany myślenia i narzędzi tylko wtedy, gdy Ollama mówi, że może je zabrać.

    MASTERMIND_TEAM=gemma task mastermind:ask -- "..."   # gemma4 answers, functiongemma calls tools,
                                                     # translategemma translates, shieldgemma guards
task mastermind:compare                              # every team, the questions of questions.yaml
task mastermind:compare -- bielik qwen               # only these
task resources:push -- conversations                 # what they said, to their dataset

    Na przestrzeni demo: własny odwiedzający Hugging Face¶

    Karta zapytaj o prawo przeglądarki (#ask) jest tym samym mastermind jak czat: każdy cytowany akt link do jego strony, akty, które nazwał bez czytania je oznaczone ?Jego rozumowanie się złożyło.

    Na przestrzeni demo (faza 32) działa na własnym koncie odwiedzającego, podobnie jak inne miejsce właściciela: karta miejsca prosi o hf_oauth z zakresem stosowania inference-api, znaki gości z Hugging Face (/login), a token pozostaje w pamięci serwera za ciasteczkiem HttpOnly - nigdy nie dociera do przeglądarki, pliku lub dziennika. Następnie:

    • model poprzez dostawców informacji (https://router.huggingface.co/v1), google/gemma-4-26B-A4B-it domyślnie (DEMO_MODEL; DEMO_URL za kolejne api), wypłacane z kredytów odwiedzającego;
    • pytanie wektor przez BAAI/bge-m3 na Hugging Face, ten sam model co wektory zbioru danych, które przestrzeń zajmuje na pierwszym pytaniu (około 760 MB);
    • jedno pytanie naraz na gościa, cztery naraz w ogóle; rozmowa gościa nie jest zachowana.

    Gość bez kredytów dostaje odpowiedź Hugging Face: "Purchase pre-paid credits to continue using Inference Providers". Znaki kosmiczne w nikim bez hf_oauth w swojej karcie, oraz /api/ask wtedy tak mówi.

    Zmienna Domyślne Co to jest?
    DEMO_MODEL google/gemma-4-26B-A4B-it model na przestrzeni
    DEMO_URL https://router.huggingface.co/v1 jego OpenAI- like api
    OAUTH_CLIENT_ID, OAUTH_CLIENT_SECRET, OPENID_PROVIDER_URL, SPACE_HOST set by Hugging Face Podpisanie

    Czego się spodziewać?¶

    deepseek-r1:8b on an RTX 3060 answers in 30 seconds to a few minutes, most of it thinking. It is the smallest voice of the plan: it now and then answers in English, slips a word of another script into Polish, or cites an act it did not open - which the check marks. The larger deepseek of phase 34 (the advanced strategy above) is for the hard questions.
