    Von Rohdateien zu Tabellen und Texten¶

    task seal                 # checksums for gathered files that have no record yet
task seal -- --check      # read every recorded file again, name the ones that differ
task compile              # tables: details and references of acts, a year in a file
task text                 # markdown from gathered HTML, with checksums
task text -- --pdf        # and from the PDFs of acts without HTML (poppler-utils)

    Keiner von diesen fragt etwas im Internet. Sie lesen resources/bucket/ und schreiben in resources/dataset/Jeder kann jederzeit wiederholt werden.

    Checksums: seal¶

    Ein Bucket auf Hugging Face gibt keine Prüfsumme einer Datei, so dass das Projekt seine eigene behält. Eine Zeile pro Datei in dataset/files/<journal>/<year>.jsonl:

    {"path":"DU/1918/WDU19180010001.json","size":3578,"sha256":"0c1f2c7e...","url":"https://api.sejm.gov.pl/eli/acts/DU/1918/1","gatheredAt":"2026-10-13T13:25:12.282Z"}
    Feld Bedeutung
    path Die Datei, innerhalb des Buckets
    size, sha256 von der Datei, wie sie geschrieben wurde
    url Woher es genommen wurde
    gatheredAt wann

    Der Sammler schreibt den Datensatz in dem Moment, in dem eine Datei auf der Festplatte landet, bevor irgendetwas irgendwohin gesendet wird. task seal ist für Dateien gesammelt, bevor Datensätze existierten: es schreibt die fehlenden Datensätze, mit der Änderungszeit der Datei als gatheredAt.

    task seal -- --check liest jede aufgezeichnete Datei, die hier ist und vergleicht. Es druckt die Pfade, die sich unterscheiden und endet mit einem Fehler, wenn es welche gibt. Führen Sie es aus, nachdem Sie den Eimer zu einer anderen Maschine gezogen haben, oder vor einem großen Schub.

    Wenn eine Datei mehrere Datensätze hat, ist die letzte die aktuelle.

    Tables: compile¶

    Details und Referenzen sitzen im Bucket als eine kleine Datei pro Akt. Zum Lesen in großen Mengen werden sie zusammengestellt, ein Jahr in einer Datei:

    Tabelle Eine Linie ist hergestellt aus
    dataset/details/<journal>/<year>.jsonl die Details einer Handlung, wie die API ihnen gab <address>.json
    dataset/references/<journal>/<year>.jsonl Eine Bindung zwischen zwei Akten Feld references Einzelheiten

    Eine Zeile der Referenztabelle:

    {"from":"DU/1918/2","type":"Uchylenia wynikające z","to":"DU/1918/23","date":"1918-10-21"}
    Feld Bedeutung
    from ELI des gesetzes, dessen details den gleichstand benennen.
    type Art der Krawatte, von lists/reference_types.json
    to ELI des anderen Gesetzes
    date, art wenn die API Ihnen

    Alle Referenztabellen zusammen sind die Graphik des Gesetzes: Welche Handlung ändert, hebt oder führt welche aus. Die ersten sechzehn Jahre von Dziennik Ustaw geben 45,658 Bindungen für 11,008 Akte.

    Taten, deren Einzelheiten noch nicht zusammengetragen wurden, werden ausgelassen. Tabellen werden bei jedem Lauf ganz geschrieben.

    Texts: text¶

    Jede gesammelte HTML wird zu einer markdown-Datei, dataset/texts/<journal>/<year>/<address>.mdund eine Linie in dataset/texts/<journal>/<year>.jsonl verbindet es mit seiner Quelle:

    {"ELI":"DU/1918/2","markdown":"texts/DU/1918/WDU19180020002.md","sha256_md":"a85ee287...","sha256_html":"1fd223bc...","url":"https://api.sejm.gov.pl/eli/acts/DU/1918/2/text.html"}
    Feld Bedeutung
    markdown die markdown-Datei, innerhalb des Datensatzes
    sha256_md Prüfsumme des markdown
    sha256_html Prüfsumme des HTML wurde aus
    url die HTML an der Quelle

    Eine HTML, deren Prüfsumme sich nicht geändert hat, wird nicht wieder analysiert.

    Wie der markdown aussieht:

    # Ustawa z dnia 4 lutego 1918 r. o Radzie Stanu Królestwa Polskiego

## Treść ustawy

### Art. 1.

Rada Stanu Królestwa Polskiego z siedzibą w mieście stołecznem Warszawie składa się ze 110 członków, a mianowicie:

a) 12 członków wirylistów,

    Artikel, Absätze ()§) und Kapitel sind Überschriften. Punkte und Buchstaben öffnen ihre eigene Linie. Skripte und Buttons des Sejm-Readers werden entfernt.

    Denken Sie daran! Die markdown wurde nur auf Taten von 1918 bis 1933 betrachtet. Neuere Handlungen können HTML verwenden, die dieser Parser nicht erfüllt hat, und Tabellen werden nicht in markdown Tabellen umgewandelt. Lesen Sie ein paar neue, bevor Sie es in großen Mengen vertrauen.

    Nur HTML wird analysiert: 39,110 von 164,638 Akten haben es, alle in Dziennik Ustaw. Die anderen drei Viertel haben nur eine PDF und erhalten noch keine markdown.

    Arbeitsplan¶

    gather ──► seal (once, for old files) ──► compile ──► text ──► resources:push

    Texte von PDFs¶

    task text -- --pdf gibt markdown zu Taten, die nur eine PDF haben. Die Textschicht wird gelesen von pdftotext von Popplerscripts/install.sh Anlagen poppler-utils), die den beiden Spalten einer Zeitschrift Seite folgt. Zeilen werden zu Absätzen, ein am Ende einer Zeile geschnittenes Wort wird zurückgeklebt und Art. 1., § 1. und Rozdział 1 werden Überschriften, wie in markdown von HTML. Vier PDFs werden gleichzeitig gelesen ()--parallelEin Jahr mit 1200 Akten dauert einige Sekunden.

    Die meisten PDFs vor den 2000s sind Scans, die Adobes Paper Capture eine Schicht erkannten Textes gab. Dieser Text bleibt so, wie er ist, mit seinen Fehlern: Nichts wird durch Raten korrigiert. Die Platte benennt den Hersteller des PDF, so dass ein Leser diese Texte unterscheiden kann:

    {"ELI":"DU/1953/228","markdown":"texts/DU/1953/WDU19530460228.md","sha256_md":"...","from":"pdf","sha256_pdf":"...","producer":"Adobe Acrobat 9.0 Paper Capture Plug-in","url":"https://api.sejm.gov.pl/eli/acts/DU/1953/228/text.pdf"}

    Ein PDF ohne Textschicht (weniger als 40 Buchstaben auf allen Seiten, etwa einer von hundert) erhält keine markdown; es wird in dataset/texts/<journal>/<year>.scans.jsonl und wartet auf OCR. Wenn ein Akt später seinen HTML bekommt, wird der markdown wieder aus dem HTML gemacht.

    ohne --pdf, task text hält die Texte aus PDFs so, wie sie sind.

    Leser sagen, welche Texte das sind: ein Akt im api hat text.from (html oder pdf) mit dem Produzenten und der Adresse der Quelle, die Antwort von /api/acts/<journal>/<year>/<pos>/text trägt den Header X-Text-FromDas MCP-Tool act_text öffnet einen solchen Text mit einer Zeile, die seinen PDF nennt, und der Betrachter legt eine Notiz darüber.

    Die Karte des gesamten Gesetzes: map¶

    task map                        # every preset into dataset/map/
task map -- statutes-in-force   # one

    Alle 165 Tausend Akte mit 750 Tausend Bindungen sind zu viele für eine Seite, so dass ein Preset einen Teil von ihnen nimmt, mit den Bindungen zwischen seinen Akten von dataset/references/:

    Preset Rechtsakte Krawatten (2026-11-22)
    statutes-in-force Statuten (ustawy) in Kraft 2,848 / 2,234
    statutes Jede Satzung seit 1918 9,985 / 71,489
    in-force Jede Handlung in Kraft 20,484 / 11,953
    statutes-in-force-by-meaning geltenden Statuten, die einen Vektor haben (task embed), jedes gebunden an seine 5 nächsten durch Bedeutung anstelle der Bindungen der Quelle So viele wie Vektoren

    ForceAtlas2 platziert sie einmal, hier (etwa eine Minute für alle drei), so dass ein Browser nur zeichnet: Die Registerkarte "map of the whole law" des Betrachters zeigt sie mit sigma.js, /api/map/<preset> gibt ihnen. Lauf task compile Erstens sind die Krawatten frisch. Die Dateien gehen zu Hugging Face mit dem Datensatz, so dass die Demo sie zeigen kann.

    Suchen Sie jedes Jahr: search:index¶

    task init                                         # once: resources/secrets/typesense_api_key
docker compose --profile search up -d typesense   # Typesense 30.2 on 127.0.0.1:8108
task search:index                                 # titles, types, statuses, keywords
task search:index -- --texts                      # and the first 2000 characters of each text

    Jeder Akt geht in die Sammlung acts (ein bereits vorhandener Akt wird ersetzt). Titel, Schlüsselwörter und Texte werden als Polnisch tokenisiert. Die api Antworten /api/search?q=...&type=&status=&journal=&page= mit Taten, die markierten Wörter ihrer Texte und zählt pro Typ, Status und Zeitschrift. Der Betrachter zeigt ein Feld "every year", wenn die Suche antwortet. Ohne Typesense, /api/search Antworten 503 und sagt, wie man es beginnt, und nichts anderes ändert sich. Alle 165 Tausend Akte dauern 10 Sekunden; mit Texten 20 Sekunden und etwa 450 MB Speicher im Dienst.

    Textvektoren: embed¶

    ollama serve &              # or: docker compose --profile llms up -d llms-ollama
ollama pull bge-m3          # once, about 1.2 GB
task embed                  # every text; task embed -- 2026 for one year

    Jeder Akt mit markdown erhält einen Vektor: seinen Titel und die ersten 2000 Zeichen seines Textes, die einem lokalen mehrsprachigen Modell durch Ollama gegeben werden.EMBED_MODEL, bge-m3 standardmäßig: 1024 Nummern, Polnisch unter seinen Sprachen. Sie gehen neben die Texte, in dataset/embeddings/<model>/<journal>/<year>.parquet (ELI, sha256_md, vector, und model.json Sagt, wie sie gemacht wurden. Ein Akt, dessen markdown sich nicht geändert hat, behält seinen Vektor, so dass ein Lauf wiederholt wird, um das Neue zu nehmen.

    DU 2020 (2453 Akte) dauerte 1 Minuten 46 Sekunden auf einer GeForce RTX {10} und 4 MB. Das ganze Gesetz würde ungefähr zwei Stunden und 670 MB dauern.

    Suche nach Bedeutung¶

    Mit den Vektoren gemacht, task search:index setzt sie auch in Typesense (eine bestehende Sammlung erhält das Feld, ohne neu gemacht zu werden). Eine Suche nach jedem Jahr mit meaning=1 verwandelt die Frage in einen Vektor nach dem gleichen Modell von Ollama, und Typesense ordnet Handlungen nach Wörtern und Bedeutung zusammen. Eine Frage im Englischen findet polnische Taten: "protection of children against violence at school" fanden die Taten des Bildungsministers zur Sicherheit in Schulen, wo die Worte allein einen Akt fanden. Ohne Ollama sagt die Suche meaning: false und arbeitet nur mit Worten. Der Viewer zeigt die Box "by meaning, in any language" nur, wenn der Host es kann.
