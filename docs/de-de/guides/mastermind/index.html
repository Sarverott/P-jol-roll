    Das Law Mastermind¶

    Die erste Stimme des Gesetzes Mastermind (Phase 30; Plan des Eigentümers in) Q18): eine Frage in Worten, die von einem Modell beantwortet wird, das die Handlungen durch die eigenen MCP-Tools des Projekts liest und jede Handlung, auf die es sich stützt, durch seine ELI zitiert. Keine (formal) RechtsberatungEin anwalt des teufels, den sich jeder leisten kann.

    Wie es antwortet¶

    1. Die Taten, die der Bedeutung am nächsten sind. Die Frage wird zu einem Vektor des Modells, das die Vektoren von task embed (bge-m3) und das MCP-Tool search_meaning Vergleicht es mit dem vektor jeder handlung jedes jahres.
    2. Ihre Texte. Die Texte der nächsten drei ()act_text) gelesen und dem Modell mit der Frage gegeben.
    3. Rounds. Das Modell kann jedes Werkzeug aufrufen - act, act_text, search_acts, search_meaning, ... - für höchstens sechs Runden, dann Antworten.
    4. Die Zitate überprüft. Alle [DU/<year>/<position>] Die Antwort ist markiert read wenn das Modell geöffnet wurde, das durch ein Werkzeug wirkt, und nicht lesen als er es aus dem Gedächtnis benannte.

    Auf dieser Maschine: Ollama des Gastgebers¶

    Entwicklung verwendet das Ollama des Gastgebers ()http://127.0.0.1:11434und seine GPU, mit deepseek-r1:8b und bge-m3 hineingezogen:

    task mastermind:ask -- "Kto płaci podatek dochodowy od osób fizycznych?"
task mastermind:ask -- --json "..."        # with the reasoning and the tools it called
MASTERMIND_URL=http://127.0.0.1:11434 task serve
curl -G http://127.0.0.1:8080/api/ask --data-urlencode "question=..."

    Auf einer anderen Maschine: komponieren¶

    Das Profil mastermind bringt alles als Container: llms-ollama, llms-models (zieht die Modelle einmal, dann endet) und mastermind - das Image des Webapp-Servers mit einem Mastermind-Set, Serving /api/ask, /mcp und der Betrachter auf 127.0.0.1:8081.

    task resources:pull -- dataset             # the acts and their vectors (dataset/embeddings/)
task mastermind:up                         # the GPU given to Ollama when nvidia-smi answers
docker compose logs -f llms-models         # the first start downloads about 6 GB
curl -G http://127.0.0.1:8081/api/ask --data-urlencode "question=..."
task mastermind:down

    Handschrift: docker compose --profile mastermind up -d, und -f compose.yaml -f resources/services/gpu.yaml vor --profile für die NVIDIA-Karten (das NVIDIA Container Toolkit wird für sie benötigt).

    The advanced strategy: a deepseek hosted by Hugging Face¶

    The owner's plan (Q18, phase 34): small models on the host first, the hard questions to a large deepseek hosted by Hugging Face. src/mastermind/strategy.ts:

    • --escalate: the usual model answers first; its answer goes on when it is weak - it says nothing, cites no act, or cites an act it never opened. The large one, deepseek-ai/DeepSeek-R1-0528 through Inference Providers (https://router.huggingface.co/v1; novita, deepinfra and featherless-ai serve it), gets the small one's answer to check, never to trust, and reads the acts itself through the same MCP tools.
    • --hard: straight to it.
    task mastermind:ask -- --escalate "Czy mogę odliczyć ulgę na dziecko po rozwodzie?"
task mastermind:ask -- --hard "..."
curl -G http://127.0.0.1:8080/api/ask --data-urlencode "question=..." -d escalate=1

    Here it is paid by HF_TOKEN von .env - the owner's own, so only a question the owner asks spends it; on the space by the signed-in visitor's token. The chat shows a switch a hard question when the host can pay for it (hard von /api/ask/about), and folds what the smaller model said first. The large one's conversation is kept with escalated: the small model, why its answer went on, what it said and where that is kept.

    Variabel Ausfall Was es ist
    HARD_MODEL deepseek-ai/DeepSeek-R1-0528 the model of hard questions
    HARD_URL https://router.huggingface.co/v1 OpenAI-like api
    HARD_KEY HF_TOKEN the token it is paid by

    Not yet seen answering for real: Inference Providers refuse the owner's token with 402 until it has credits (phase 32); it is tested against a stand-in of them.

    The Python stack¶

    The models and the simulations have a stack of their own (phase 34): stacks/python/, a uv project reading the law through the same MCP tools (Law) and asking the mastermind through /api/ask (Mastermind). task python:check, task python:law -- nearest "obowiązek szkolny".

    The executive agent¶

    Not a chat but a task (phase 33): a small qwen does what a person gives it, reading the law through the MCP tools, and writes what it is asked for into resources/agent/ - the only place it can write; it runs no command and fetches no page.

    task agent -- "Przeczytaj dekret DU/1919/147 i zapisz w pliku obowiazek-szkolny-1919.md streszczenie"
task agent:container -- "..."     # the same in the agents' shell, with Ollama of the profile llms

    Its first real task, on this machine: it read the school decree of 1919 and wrote resources/agent/obowiazek-szkolny-1919.md - school age from 7, seven years of school, to 14 - citing the articles, the act marked read. Every run is kept as a conversation (resources/conversations/qwen/...).

    Two engines (AGENT_ENGINE):

    • own (the default): the mastermind's rounds with the MCP tools given directly, and one tool of its own, write_note (a bare file name, markdown, never outside resources/agent/); its instructions are resources/configs/mastermind/executive.md.
    • opencode: opencode 2 as its host, as planned, from resources/configs/agentic-shell/opencode/ - its own config and data directories (resources/.containerdatavol/agent/), so neither the person's opencode settings nor sessions are touched, --standalone, a model of its own with a 24k context. Not yet reliable: opencode 2 hands an MCP server's tools over through Code Mode, and in some runs it does not find the server's namespace (Unknown tool 'p-jol-roll.act_text').
    Variabel Ausfall Was es ist
    AGENT_MODEL qwen3:8b the model
    AGENT_OLLAMA_URL http://127.0.0.1:11434/v1 its Ollama (http://llms-ollama:11434/v1 in the shell)
    AGENT_ENGINE own own oder opencode
    AGENT_ROUNDS, AGENT_CONTEXT 8, 24576 rounds of tools (own); context of its model (opencode)

    Ollama auf eigene Faust¶

    Die Modelle sind groß und viele, so dass das Ollama dieser Maschine sie auf einem eigenen Antrieb hält: OLLAMA_MODELS in .env (die Variable Ollama selbst liest) benennt das Verzeichnis.

    task ollama:where        # where they are read from, and how many are there
task ollama:serve        # the first start copies ~/.ollama/models there, then serves from there
task ollama:copy         # the copy again: only what is missing, then checked

    Das alte Verzeichnis wird von ihnen nie gelöscht. Stoppen Sie das Ollama, das zuerst läuft ()ss -ltnp | grep 11434 Das zeigt es. Ein Laufwerk, dessen root zu root gehört, benötigt sein Verzeichnis einmal: task ollama:serve sagt: sudo line.

    Die Gespräche hielten¶

    Jede Frage wird mit allem Gesagten beibehalten, so dass Modelle und Familien verglichen werden können:

    resources/conversations/<family>/<instance>/<UNIXUSAT>-<the question's first words>.json
resources/conversations/deepseek/deepseek-r1-8b/1795498362594-czym-byla-rada-stanu-w-1918-roku.json

    Die Familie kommt aus resources/configs/mastermind/families.yaml (Die Modelle einer Familie agieren als ein Team): gemma4, translategemma, embeddinggemma, shieldgemma... sind alle gemmaDie Instanz ist das Modell mit seiner Größe. Eine Datei enthält die Frage, die Antwort, die Begründung, die zitierten Handlungen, die aufgerufenen Werkzeuge, wie lange es gedauert hat und den gesamten Austausch - die Texte und was die Werkzeuge geantwortet haben. Das Verzeichnis ist die lokale Seite ihres eigenen Datensatzes, Apokryf/Consiliariis-Polonicum-Lex (conversations von resources/.map.json): task resources:push -- conversations sendet, was neu ist, die Bewegung einer Person; git behält nur seine Karte. MASTERMIND_KEEP=0 hält nichts. Beim Komponieren ist es das eine Verzeichnis, das der Mastermind schreibt.

    Familien als Teams¶

    resources/configs/mastermind/families.yaml die Familien und ihre Teams benennen: ein Modell antwortet, eines nennt die Werkzeuge in den Runden, eines verwandelt eine in einer anderen Sprache gegebene Antwort in die Frage, eines wacht (sein Urteil gehalten, nichts zurückgehalten). Ein Modell erhält nur dann Denken und Werkzeuge, wenn Ollama sagt, dass es sie nehmen kann.

    MASTERMIND_TEAM=gemma task mastermind:ask -- "..."   # gemma4 answers, functiongemma calls tools,
                                                     # translategemma translates, shieldgemma guards
task mastermind:compare                              # every team, the questions of questions.yaml
task mastermind:compare -- bielik qwen               # only these
task resources:push -- conversations                 # what they said, to their dataset

    Auf dem Demo-Space: der Besucher eigene Hugging Face¶

    Der Tab Fragen Sie das Gesetz Der Betrachter ()#ask) ist das gleiche mastermind wie ein chat: jeder zitierte akt einen link zu seiner seite, die handlungen, die er benannt hat, ohne sie zu lesen, markiert mit. ?, seine Argumentation gefaltet.

    Auf dem Demo-Space (Phase 32) läuft er auf dem eigenen Konto des Besuchers, wie der andere Space des Besitzers: die Space-Karte fragt nach hf_oauth mit dem Anwendungsbereich inference-api, meldet sich der Besucher mit Hugging Face an (/login), und das Token bleibt im Speicher des Servers hinter einem HttpOnly-Cookie - es erreicht niemals den Browser, eine Datei oder ein Protokoll. Dann:

    • das Modell durch Inference Provider ()https://router.huggingface.co/v1), google/gemma-4-26B-A4B-it StandardmäßigDEMO_MODEL; DEMO_URL für weitere api, bezahlt aus den Credits des Besuchers;
    • Die Frage nach einem Vektor durch BAAI/bge-m3 auf Hugging Face das gleiche Modell wie die Vektoren des Datensatzes, den der Raum auf seine erste Frage nimmt (ca. 760 MB);
    • eine Frage nach der anderen pro Besucher, insgesamt vier auf einmal; das Gespräch eines Besuchers wird nicht geführt.

    Ein Besucher ohne Credits erhält die eigene Antwort von Hugging Face: "Purchase pre-paid credits to continue using Inference Providers"Die Raumzeichen in niemandem ohne hf_oauth auf seiner Karte und /api/ask Dann sagt es so.

    Variabel Ausfall Was es ist
    DEMO_MODEL google/gemma-4-26B-A4B-it Das Modell im Weltraum
    DEMO_URL https://router.huggingface.co/v1 OpenAI-like api
    OAUTH_CLIENT_ID, OAUTH_CLIENT_SECRET, OPENID_PROVIDER_URL, SPACE_HOST Set von Hugging Face Unterzeichnung

    Was zu erwarten ist¶

    deepseek-r1:8b on an RTX 3060 answers in 30 seconds to a few minutes, most of it thinking. It is the smallest voice of the plan: it now and then answers in English, slips a word of another script into Polish, or cites an act it did not open - which the check marks. The larger deepseek of phase 34 (the advanced strategy above) is for the hard questions.
