    Übersetzungen¶

    Die Idee des Eigentümers (Q15, Changelog Phase 12): Seiten werden nicht mit Namen von Texten und Loadern umgeschrieben. Ihre textknoten werden gefunden, von einem SHA-256 von dem, was sie sagen, und ihr inhalt wird aus einem sprachpaket ersetzt. Phase 16 hat es zuerst überprüft, in src/i18n/ mit tests/i18n.test.tsDiese Seite sagt, was herausgekommen ist.

    Wie es funktioniert¶

    "115 acts"  -> normalized, numbers as holes -> "{0} acts" -> SHA-256 -> 6f1c...e2
pack PL-PL: "6f1c...e2": { "one": "{0} akt", "few": "{0} akty", "many": "{0} aktów" }
            -> "115 aktów"
    • src/i18n/sha256.ts: SHA-256, synchron, das gleiche in einem Browser, in einem Knoten und in einem Terminal (geprüft gegen den eigenen Knoten).
    • src/i18n/hooks.ts: hookOf(text), translate(pack, text), und t(pack, text) für ein Terminal: der Text des Pakets oder das Englisch, wenn das Paket keinen enthält. Eine Zahl in einem Text ist ein Loch, so dass "3 acts" und "115 acts" ein Eintrag sind; ein Eintrag kann die Pluralformen seiner Sprache enthalten.Intl.PluralRules), gewählt durch die erste Zahl.
    • src/i18n/dom.ts: collect(root) gibt jedem Haken einer Seite mit seiner englischen Vorlage (so wird das Standardpaket erstellt), apply(root, pack) legt eine Packung über die Seite und apply(root, undefined) gibt das Englisch zurück, das pro Knoten erinnert wird. follow(root, pack) hält das Rudel darüber, was ein Framework später macht.

    Was übersetzt wird: Was markiert ist¶

    Seit Phase 21 benennt eine Seite, was ihre Schnittstelle ist, nach Klassen; nichts anderes wird berührt:

    Klasse Übersetzt
    i18n-texts-slot Jeder Text unter dem Element und die lesbaren Attribute dessen, was darunter ist
    i18n-texts-placeholder das placeholder dieses Elements
    i18n-texts-title / i18n-texts-alt / i18n-texts-label als title / alt / aria-label

    Innerhalb eines Slots bleiben Daten unter translate="no" Code wird übersprungen. Die Einführung ist ein Slot (es) <main>), markiert der Betrachter seine Teile einzeln und die Dokumentation wird von seinem Builder als ein Slot markiert.

    Was funktioniert¶

    Geprüft Wie
    Textknoten und die Attribute, die die Leute lesen ()placeholder, title, aria-label, alt) Eine Seite in LinkedIn
    Zahlen und Pluralformen (1 akt, 3 akty, 115 aktów) t() und die Seite
    nur das, was durch die oben genannten Klassen gekennzeichnet ist; darin werden Daten nie übersetzt: Titel und Texte von Handlungen sitzen darunter translate="no", hat das Attribut HTML dafür; code und pre auch übersprungen werden die Seite
    zurück ins Englische oder in eine andere Sprache, ohne Nachladen die Seite
    was Vue später macht: Ein geschriebener Textknoten hält wieder Englisch, der Beobachter übersetzt es wieder; das Englisch, an das er sich erinnert, wird fallen gelassen Jsdom als Browser
    ein Pack für jedes Interface: derselbe Haken in einer Seite, der Launcher und die CLI t() Nimmt einfache Strings

    Vue patcht einen Textknoten, indem er seine nodeValue nur wenn sich der eigene virtuelle Text ändert und das DOM nie wieder gelesen wird. Ein übersetzter Knoten bleibt daher übersetzt, bis Vue ihn erneut schreibt und dann der Beobachter ihn erneut übersetzt. Die Seite und das Framework kämpfen nicht.

    Was nicht und was dagegen getan wird¶

    • Ein Satz geschnitten durch Markup ("die") PDF an der Quelle ist der Text") gibt Fragmente, jeder süchtig allein. " Die Reihenfolge der Wörter unterscheidet sich zwischen den Sprachen, so dass Fragmente schlecht übersetzt werden. Solche Sätze erhalten ihren eigenen kurzen Wortlaut oder ein Element, das später als eine Einheit markiert wird.
    • Das gleiche Englisch, zwei Bedeutungen ("status" als Spalte und als Zustand) ist ein Haken. Wenn es darauf ankommt, wird das Element data-i18n-context, die den Haken salzt (noch nicht benötigt).
    • Ändern der englischen Waisenkinder seine ÜbersetzungWeil sich der Haken verändert. Die Packung behält das Englisch von jedem Eintrag, so dass das Skript, das Packungen macht, Waisenkinder findet und das neue Englisch wieder übersetzt; alte Einträge werden fallen gelassen.
    • Suchmaschinen sehen keine Übersetzung im Browser. Die Einführung und die Dokumentation werden daher übersetzt, wenn die Website erstellt wird, von der gleichen apply() über den gebauten HTML, in /<language>/ Kopien. Der Viewer wird im Browser übersetzt.
    • Die englischen Blitze Bevor eine Packung kommt. Die Packung wird vor dem Montieren des Betrachters geladen.

    So bleibt die Idee, ohne Texte, die im Code genannt werden: Die Seiten bleiben wie geschrieben, die Benutzeroberfläche wird durch Klassen und Daten durch ein Standardattribut gekennzeichnet, und eine kleine Bibliothek dient dem Browser und dem Terminal.

    Sprachpakete¶

    resources/locales/ enthält eine JSON-Datei pro Sprache, aufgeführt in resources/locales/.index.json mit EN-US den Standard. Seit Phase 28 ist es ein Git-Submodul: Die Packungen leben in ihrem eigenen gist0b86ecd07d55426754759bdff{87}d4), die Quelle, die das Projekt liest - ein frischer Klon nimmt es durch git submodule update --init resources/locales (task i18n:pull, und task init Sagt, wenn es fehlt.

    Packung Hergestellt von
    EN-US.json task i18n:collect: die eingebaute Einführung und Viewer in einem Headless Browser geöffnet, ihre eigene Laufzeit sammelt jeden Text mit seinem Haken
    PL-PL.json, UK-UA.json, DE-DE.json task i18n:translate: argostranslate (die Engine von LibreTranslate), Modelle einmal heruntergeladen 
    task web:build && npm run --prefix webpage build    # both pages built
task i18n:collect                                   # their English -> EN-US.json
task i18n:translate                                 # what the other packs miss
task i18n:translate -- PL-PL --again                # one pack anew (not its reviewed entries)
task i18n:publish -- "the texts of phase 28"        # committed in the gist, pushed, the submodule staged

    Eine hier geänderte Packung (von einer Person gesammelt, übersetzt oder überprüft) erreicht alle erst nach task i18n:publish: Der gist erhält den Commit und dieses Repository den neuen Commit des Submoduls mit dem nächsten Schritt. Die Workflows, die bauen, nehmen die Packs von git submodule update --init resources/locales.

    • Ein Text mit einer Zahl wird einmal pro Pluralform der Sprache übersetzt, mit der Zahl, die die Form annimmt ()plural im Index: Polnisch 1, wenige 3, viele 5), und die Zahl wird wieder zum Loch.
    • Namen in keep des Index (Dziennik Ustaw, Sejm, SAOS, P_JOL_ROLL...) werden nie übersetzt: Sie stehen als Zahlen, während das Modell funktioniert, weil Buchstaben von einigen Modellen transliteriert werden und Zahlen nie tun.
    • Maschinelle Übersetzung macht Fehler ("Bucket" wurde "Bukiet"). Eine Person fixiert einen Eintrag in der Packung und listet ihren Haken auf reviewedDas Skript überschreibt niemals einen überprüften Eintrag und lässt ihn niemals fallen.
    • Eine Sprache wird durch eine Zeile im Index hinzugefügt (mit seiner argos Paar) und task i18n:translate.

    Der Betrachter und die Einführung nehmen die Packung von ?lang=PL-PL, sonst die letzte Wahl, sonst die Sprachen des Browsers, sonst Englisch. Sie laden nur dieses Paket und legen es über die Seite, bevor es angezeigt wird, und ein Schalter im Header ändert es ohne erneutes Laden.

    Die Dokumentation wird übersetzt, wenn die Website erstellt wird (scripts/devops/pages/build.sh Läufe src/devtools/docs-i18n.ts): Die gebaute MkDocs-Site wird kopiert in site/docs/pl-pl/, uk-ua/ und de-de/, und jede Packung wird über die Führungen, das Glossar und die Homepage von der gleichen gelegt apply() Der Browser nutzt. Das Changelog und das Devlog bleiben in jeder Kopie auf Englisch, weil sie die Worte des Besitzers Wort für Wort behalten. Jede Seite erhält eine Liste von Sprachen in ihrer Kopfzeile, die auf die gleiche Seite in jeder Kopie zeigt. Read the Docs baut nur die Engländer.

    Identifikatoren werden nie übersetzt: ein Text, der ein Pfad oder ein Name ist ()datasets/Sarverott/polish_national_law_docs) bekommt keinen Haken, und einer in einem Satz (resources/.map.json, SHA-256, v0.11.0) steht als Zahl, während das Modell funktioniert, wie die Namen von keep.

    Das Terminal¶

    Der Launcher (Blatt) task), seine REPL und die Listen der Aufgaben sprechen die Sprache des Terminals: P_JOL_ROLL_LANG=PL-PL task, Sonstige LANG (pl_PL.UTF-8 gibt PL-PL), sonst Englisch. Die Beschreibungen der Aufgaben sind das Handbuch der CLI, so dass sie auch übersetzt werden.

    In code wird ein text einmal geschrieben, in englisch, durch. tr() (src/i18n/terminal.ts):

    tr("task {name} ended with {code}", { name, code })

    Das Englisch ist der Haken, wie auf Seiten. Benannte Stellen in Zahnspangen werden gefüllt, nachdem die Packung gelegt wurde, so dass eine Übersetzung sie dorthin bringt, wo ihre Sprache sie haben will. Während das Modell funktioniert, stehen sie als Zahlen, wie zitierte Befehle ()"list", "gather -- 2026"So wird weder übersetzt. task i18n:collect findet jeden tr("...") von src/ und die Beschreibung jeder Aufgabe selbst. Tests laufen auf Englisch unabhängig LANG Die Maschine hatvitest.config.ts).
