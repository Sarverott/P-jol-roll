    Sammeln¶

    task gather                                  # lists, and metadata of the newest year, every journal
task gather -- 2025 2026                     # metadata of these years
task gather -- --all                         # metadata of every year
task gather -- 2026 --acts --limit 5         # and all files of the first 5 acts that miss any
task gather -- 2026 --parts pdf,html         # only these files
task gather -- --publisher MP                # one journal (DU, MP); can be repeated
task gather -- 2026 --acts --rate 60         # slower: 60 requests per minute
task gather:everything                       # everything the API has; asks before it starts
task gather:changes                          # acts changed since the previous such run
task gather:changes -- 2026-10-01            # acts changed since that day

    Die Quelle ist die ELI API von Sejm, https://api.sejm.gov.pl/eliEs ist ein offenes API, also verwendet der Sammler einfache Anfragen, ohne Browser, und sagt, wer es im User-Agent ist.

    Was One Run macht¶

    first walk
GET /                  index: names of everything the API gives
 └─ every list_*       statuses, types, reference types, keywords, institutions, journals
     └─ journals       DU and MP, each with its years
         └─ year       every act of the year, in one answer

second walk, one year after another
year ── act            the files that are not here yet
         └─ texts      other texts of the act, named in its details
    1. Der Index wird gespeichert als dataset/lists/index.jsonUnd jede Liste nennt sie als dataset/lists/<name>.json.
    2. Die Liste der Zeitschriften öffnet die Jahre: die neueste, die Jahre, die Sie benannt haben, oder alle mit --all.
    3. Jedes Jahr wird gerettet als dataset/acts/<journal>/<year>.jsonl, ein Akt pro Zeile, sortiert nach Position.
    4. mit --acts oder --partsDie Akten werden in bucket/<journal>/<year>/Ein Jahr nach dem anderen. Siehe die Daten für das, was jede Datei enthält.
    5. Jede Datei, die landet, erhält einen Datensatz mit ihrer Prüfsumme in dataset/files/<journal>/<year>.jsonl.

    Akten einer Handlung¶

    Teil Datei Besteht für
    details <address>.json Jede Handlung
    references <address>.references.json Jede Handlung
    pdf <address>.pdf Handlungen mit textPDF
    html <address>.html Handlungen mit textHTML
    struct <address>.struct.json Handlungen mit textHTML
    texts <address>.T.pdf, <address>.U.pdf Handlungen, deren details mehr texte benennen.

    --acts nimmt sie alle. texts werden aus den details der handlung gelesen, so dass die details hier sein müssen oder im selben lauf gefragt werden.

    Optionen¶

    Option Ausfall Bedeutung
    Jahre, als einfache Zahlen Neuestes Jahr welche Jahre. Ein Jahr, das das Journal nicht hat, wird fallen gelassen
    --all ausgeschaltet jedes Jahr der Zeitschrift
    --publisher DU Jede Zeitschrift welche Zeitschrift. Kann wiederholt werden
    --acts ausgeschaltet Nehmen Sie jede Akte jeder Handlung
    --parts details,pdf nicht nehmen nur diese Dateien
    --limit 20 20 wie viele Handlungen ein Lauf nimmt Dateien für. 0 bedeutet keine Begrenzung
    --rate 120 120 Anfragen pro Minute
    --since 2026-10-01 ausgeschaltet nur seit diesem Tag geänderte Handlungen oder last

    ohne --acts und --partsEs werden nur Listen und Listen gesammelt.

    Wann ist eine Datei "here"¶

    Eine Datei wird nicht angefordert, wenn entweder wahr ist:

    • Es liegt in resources/bucket/;
    • Es hat einen Rekord in dataset/files/.

    Die zweite Regel gilt für eine Maschine, die den Datensatz und nicht den Bucket hat: Sie fragt Sejm nicht erneut nach dem, was der Bucket bereits aufbewahrt.

    Denken Sie daran! Wenn Sie eine Datei löschen, um sie wieder aufzunehmen, löschen Sie ihre Zeilen in dataset/files/<journal>/<year>.jsonl auch. Wenn der Datensatz vorhanden ist, zählt die Datei als gesammelt.

    Anhalten und wieder anfangen¶

    Stop it with Ctrl+C Und starten Sie den gleichen Befehl erneut. Es listet die Jahre wieder auf und nimmt, was fehlt. Nichts muss wieder aufgenommen werden: Was gesammelt wird, ist aus den Akten bekannt.

    Der Sammler hält seine Warteschlange von Anfragen im Gedächtnis und schreibt nichts an storage/Die Nachricht über CRAWLEE_PURGE_ON_START Crawlee-Drucke bei Unterbrechung gelten hier nicht. A storage/ Das von früheren Versionen hinterlassene Verzeichnis kann gelöscht werden.

    --limit zählt Handlungen, die mindestens eine Datei vermissen, in der Reihenfolge von Zeitschriften und Jahren. So --limit 5 Fünfmal wiederholt dauert 25 Akte.

    Veränderungen an der Quelle¶

    Sejm ändert die Aufzeichnungen alter Akte ständig: ein Status, wenn ein Akt aufgehoben wird, neue Verweise, wenn ein Akt geändert wird. Zwischen dem 12. und 13. Oktober änderte sie 81 Akte.

    task gather:changes -- 2026-10-01     # the first time, with a day
task gather:changes                   # later: since the newest change seen before

    Es fragt die API, welche handlungen geändert wurden, listet ihre jahre erneut auf und nimmt die details und referenzen dieser handlungen erneut. mit --acts oder --parts Nach dem Tag nimmt es stattdessen diese Dateien. Die veröffentlichte PDF wird nie zweimal genommen, weil sich ein veröffentlichter Text nicht ändert.

    Eine Datei, deren Inhalt sich wirklich geändert hat, erhält einen neuen Eintrag in dataset/files/; der alte Datensatz bleibt darüber, so dass die Geschichte einer Datei gelesen werden kann.

    Das Datum zum Weiterfahren wird in dataset/lists/changes.json. Es wird nur geschrieben, wenn der Lauf beendet ist, ohne dass --limit.

    Denken Sie daran! Die Auflistung eines Jahres wird bei jedem Lauf erneut geschrieben, so dass sie immer so frisch ist wie der letzte Lauf, der in diesem Jahr aufgeführt wurde. Details sind so frisch wie die letzten gather:changes.

    Was es nie tut¶

    • Sie fordert keine Texte, die es nicht gibt. Die Auflistung sagt, welche Handlungen eine PDF oder eine HTML haben. Die API beantwortet eine fehlende HTML mit Status 200 und einer leeren Seite, sodass den Flaggen vertraut wird.
    • Es behandelt "the source has none" nicht als Fehler. Eine 404 wird protokolliert und nichts geschrieben.
    • Es hinterlässt keine halbe Datei. Eine Datei wird geschrieben als <name>.part und umbenannt, wenn sie vollständig sind. Nach einem unterbrochenen Lauf, .part Dateien können gelöscht werden.
    • Es akzeptiert keine falsche Antwort als PDF. Eine PDF muss beginnen mit %PDFEin leerer Text ist ein Fehler.
    • Es schreibt nicht außerhalb seines Verzeichnisses. Die Namen der Dateien stammen aus den Antworten des API. Eine Handlung oder ein Text, dessen Name das Verzeichnis verlassen könnte, wird abgelehnt.
    • Es beeilt sich nicht. Zwei Anfragen gleichzeitig. --rate Setzt das Tempo pro Minute ein.

    Wie groß ist es¶

    Zählt aus der Liste der Zeitschriften auf 2026-10-13:

    Journal Rechtsakte Jahre
    DUDziennik Ustaw 97,907 1918 bis 2026, ohne 1940 bis 1943
    MPMonitor Polski 66,730 1930 bis 2026

    Die Auflistungen sagen, 164,499 Akte haben eine PDF und 39,110 haben eine HTML, alle letzteren in Dziennik Ustaw. Alles sind dann etwa 572 Tausend Anfragen, plus die anderen Texte, deren Anzahl nur aus Details bekannt ist: bei 120 pro Minute, mehr als drei Tage ohne Pause.

    Die ersten sechzehn Jahre von Dziennik Ustaw (1918 bis 1933, 11 Tausend Akte) nahmen 10 GB in 34 Tausend Dateien. (Die Gesamtgröße ist noch nicht bekannt.)

    Wenn etwas versagt¶

    Was du siehst Was es bedeutet
    DU/1950 is cut: 500 of 800 Der API gab nur einen Teil des Jahres. Bisher nicht gesehen; wenn es passiert, melden Sie es als Bug
    ... source does not have it Die API antworteten 404. Nichts wird geschrieben; der nächste Lauf fragt erneut
    ... is empty Die Auflistung versprach einen Text und die API gab keinen. Der Crawler versucht, dann gibt auf diese Datei
    ... did not answer with pdf Etwas anderes kam anstelle einer PDF, normalerweise eine Fehlerseite
    act with unusable name Die API gab einen Akt, dessen Adresse kein Dateiname sein kann. Melden Sie es als Bug
    Requests scheitern in einer Reihe Der API kann down oder limitierend sein. Stop, wait, lower --rate, wieder anfangen

    Fehlgeschlagene Dateien fehlen einfach danach, so dass der nächste Lauf sie erneut verlangt.
