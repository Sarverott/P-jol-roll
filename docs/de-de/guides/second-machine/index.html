    Sammeln auf einer zweiten Maschine¶

    Die gesamte Quelle besteht aus Hunderttausenden von Anfragen und Arbeitstagen, so dass das schwere Herunterladen auf einer anderen Maschine mit den Daten auf einem externen Laufwerk ausgeführt werden kann. Diese Seite sagt, wie man es so einrichtet, dass es auf jedem Linux (einschließlich Parrot OS) und auf jedem Laufwerk funktioniert und wie man überprüft, was zurückkommt. Wie die Daten nach Hause reisen, ist noch offen (Q10 im DevlogBeide Wege werden beschrieben.

    Das Layout, das auf jedem Laufwerk funktioniert¶

    Was Wobei Warum
    Die Arbeitskopie und node_modules maschineneigene Scheibe, e.g. ~/__WORKSHOP/forge/sarverott/P-jol-roll npm benötigt Symlinks und ausführbare Dateien, die exFAT- und NTFS-Laufwerke nicht behalten, und Wechsellaufwerke werden normalerweise montiert noexec
    Ein Bare Repository (optional) der externe Antrieb eine einfache Fernbedienung: git clone /media/<you>/<drive>/P-jol-roll.git; git liest und schreibt nur Objekte dort
    Die gesammelten Daten den externen Antrieb, durch RESOURCES_DIR große Dateien, ganze geschrieben ().part Erstens, nichts darin ist jemals ausgeführt 
    # on the second machine
git clone https://github.com/Sarverott/P-jol-roll.git ~/__WORKSHOP/forge/sarverott/P-jol-roll
cd ~/__WORKSHOP/forge/sarverott/P-jol-roll
npm install                                   # Node 24, npm 11 (.nvmrc)
mkdir -p /media/$USER/<drive>/p-jol-roll-resources
cp resources/.map.json resources/frontends.json /media/$USER/<drive>/p-jol-roll-resources/
echo "RESOURCES_DIR=/media/$USER/<drive>/p-jol-roll-resources" >> .env
task check                                    # nothing asks the internet
task gather -- 2026 --acts --limit 5          # a small run first

    .env.example listet jede Einstellung auf; jede Aufgabe liest .env des Arbeitsexemplars ()dotenv in Taskfile.yml), so RESOURCES_DIR Set dort gilt für alle; eine variable set in der shell gewinnt darüber. npm run ... Ohne Task lesen Sie nicht .envExportieren Sie zuerst die Variable. .env wird von Git ignoriert.

    Wenn sich etwas weigert¶

    Was du siehst Ursache Was zu tun ist
    fatal: detected dubious ownership in repository git lehnt ein Repository ab, dessen Dateien einem anderen Benutzer gehören; auf exFAT und NTFS scheint jede Datei zu gehören, wer auch immer das Laufwerk montiert hat git config --global --add safe.directory /media/<you>/<drive>/P-jol-roll.git für diesen einen Pfad; besser, halten Sie die Arbeitskopie auf der internen Festplatte
    npm install scheitert mit EPERM oder symlink Fehler das Dateisystem des Laufwerks hat keine Symlinks (exFAT, FAT32) Installieren auf der internen Festplatte (das Layout oben)
    Permission denied wenn ein Haken, tsx oder task Läufe der Antrieb ist montiert noexec (findmnt -o TARGET,OPTIONS <path> zeigt es. Nichts vom Laufwerk laufen lassen; nur Daten leben dort
    Nein task Binär nach npm install npm 11 überspringt Installationsskripte, die nicht genehmigt sind package.json genehmigt @go-task/cli in allowScripts; wenn es von Hand mit einem älteren Checkout installiert wurde, laufen npm install wieder
    Hooks stoppen einen schlechten Commit nicht @go-task/cli älter als 3.54 lässt den Exit-Code fallen npm install aus dieser Version des Repository bringt 3.54

    lsblk -f zeigt, wie ein Laufwerk formatiert ist, findmnt <path> wie es montiert wird. task unittesting:parrot-os-drive zeigt die drei Ablehnungen oben auf Parrot OS mit einem FAT-Laufwerk montiert noexec, und das Layout dieser Seite, die auf dem gleichen Laufwerk arbeitet.

    Die Daten zurückbringen¶

    Die zweite Maschine sammelt, dann versiegelt, so dass jede Datei, die sie nahm, eine Prüfsumme hat dataset/files/:

    task seal            # records for anything gathered without one
task seal -- --check # reads every file again, names any that differ

    Dann eine von zwei Möglichkeiten (Q10):

    • Es drängt auf Hugging Face selbst, mit dem Besitzer-Token in .env: task resources:push -- bucket, task resources:push -- datasetDie Heimmaschine nimmt es mit task resources:pull -- dataset (und) bucket Wenn es die rohen Dateien will, dann task seal -- --check.
    • Der Drive reist nach Hause: Punkt RESOURCES_DIR Dort drauf, lauf task seal -- --checkund dann von zu Hause aus drücken.

    In jedem Fall wird eine Datei mit einem Datensatz nicht erneut angefordert, so dass zwei Maschinen, die den Datensatz gemeinsam nutzen, nicht die gleichen Dateien zweimal sammeln. Teilen Sie die Arbeit nach Journal oder nach Jahren ()task gather -- 1990 1991 --acts --limit 0 --publisher MPWenn sich beide Maschinen auf einmal versammeln.
