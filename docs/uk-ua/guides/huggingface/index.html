    Переміщення даних до Hugging Face¶

    task resources:plan -- dataset     # what differs; changes nothing
task resources:pull -- dataset     # take files that are there and not here
task resources:push -- dataset     # send files that are new or changed here; asks first
task resources:push -- bucket --batch 500   # commits of 500 files
task resources:prune -- space      # delete there what is not here; asks first; never the bucket

    Назва після -- є ключем resources/.map.json:

    Ім'я Місцева сторона На Hugging Face
    dataset resources/dataset datasets/Sarverott/polish_national_law_docs
    bucket resources/bucket buckets/Sarverott/raw-law-of-poland
    space resources/space spaces/Sarverott/docs-of-law-by-gov-in-poland
    conversations resources/conversations datasets/Apokryf/Consiliariis-Polonicum-Lex - розмови майстрами (фаза 31); її карта resources/conversations/README.md, збережені в git

    Місцеві сторони ігноруються git of this repository.

    Як він вирішує, що перемістити¶

    Порівняти файл з двома сторонами:

    1. по шляху;
    2. за розмірами;
    3. при одночасному згоді, за змістом: хеш git дає файлу, або SHA-256 для великих файлів, що зберігаються в LFS. На цьому кроці знаходиться місцевий файл.
    Файл plan Дзвінки push pull
    тут і немає Завантажити Відправити листя
    немає скачати листя вона
    з двох сторін, різні змінено надсилайте локальну листя локальної та імен
    з двох сторін, те ж саме й ні ні

    Так повторюючи витрати на один список і переходить тільки що нового. Ніщо переміщається двічі.

    Про нас Відро не дає хешу. У той же час, коли шлях і розмір погоджуються. Пропустити файл, який змінився без зміни його розміру. Проект зберігає свої власні чеки: task seal -- --check Порівняти кожен файл тут з записом, який був зібраний. Про нас обробка.

    Що це ніколи не робить¶

    • push ніколи не видаляє файл на Hugging Face. Виданий файл тут залишається - до prune запитується за назвою.
    • pull ніколи не перезаписує локальний файл.
    • .git, node_modules, .venv, __pycache__ і .part Файли ніколи не переміщуються в будь-якому напрямку.

    Кошик¶

    Потрібні HF_TOKEN в середовищі або в .env, з записом доступу.

    Файли йдуть в коміти 1000, назва P-jol-roll: 1000 files (3000 of 14170). --batch зміни кількості. Репозиторій на Hugging Face береться в більшості 128 скоєних годин; коли він відмовляється від одного, штовхач говорить, як довго він чекає, чекає і знову відправляє той самий коміс (з комісією 100, штовхач 14170 файлів зупинився на 128). Якщо натиснути зупинок в середині, запустіть його знову: коміти вже зроблені з іншого боку, а порівняння пропускає їх файли.

    Прути¶

    task resources:prune -- space Видалити на Hugging Face кожен файл, який там і не тут - файли plan список як download. Подивіться на них спочатку task resources:plan -- space. Вона йде в комісії від 1000, чекає в часі обмеження, як штовхач, і просить до його запуску. Відмовляється від відра: сирі файли можуть жити тільки на одній машині.

    Зроблено для простору, який зберіг app.py, development.md і requirements.txt після того, як він став Docker простором. При наборі даних, неприпустимо тільки після pull, або він видаляє те, що ця машина ніколи не була.

    Простір після виходу¶

    Решта простору будує нічого нового: Hugging Face зберігає образ, що він мав. З фази 22 випуск не записується в простір Dockerfile: вона зберігається в git як resources/configs/space/Dockerfile і приймає реліз, як аргумент для побудови, P_JOL_ROLL_VERSION. Hugging Face переходить в змінні простору для його побудови як аргументи побудови, тому набори релізів, які змінні та просять для свіжої збірки:

    task resources:space               # the space's files of resources/configs/space into resources/space
task resources:space:refresh       # its files from git when they differ, the variable, a fresh build, waited for (HF_TOKEN)

    Після того, як зображення знаходиться на ghcr.io. з фази 27, він також приносить власні файли простору з git (Dockerfileй hub/README.md як його README.md) коли вони розрізняються, і дочекається до тих пір, поки простір працює і його /openapi.json імена релізу - це збірка, яка не вдається, або займає більше 25 хвилин, не вдається виходу з власним повідомленням Hugging Face. Його токен - простір довірений видавець: робота має id-token: write, і GitHub's OIDC токен обмінюється на https://huggingface.co/oauth/token для токена цього простору, дійсна година; без секрету зберігається. Секрет HF_TOKEN залишатися в стані спокою. Не знаю, що це має. resources/configs/space/space.env імена простору і може стирати реліз; змінна середовища перемагає над нею (P_JOL_ROLL_VERSION=0.18.0 task resources:space:refresh).

    Простір кріпиться відро на /data, місце, де зображення зберігає кеш і журнали за замовчуванням. Своїм Dockerfile переміщається як до /tmp (RESOURCES_DIR, LOG_DIR); без цієї лінії кожна сторінка, що читається в відро як resources/ і logs/ (фаза 20).

    Які дані надходять, де¶

    Таблиці йдуть на дані та сирі файли актів, які йдуть на відро.

    Змішаний набір на Hugging Face - git repository. Xet, зберігання за ним, вирішує розмір файлів: великі файли зрізаються на шматки, курка, яка вже була відправлена знову не відправлена, і git зберігає тільки невеликий тостер. Вона не змінює, скільки файлів git має відстежувати. Рекомендації Hugging Face для git repository ще стоять (читати на 2026-10-13):

    Що Рекомендовані
    Файли в репозиторію до 100 тис.
    записи в одній папці до 10 тис.
    Файли в одному комітуванні до 100

    Відро - це зберігання об'єктів на одному Xet, без git, і ця сторінка говорить ці рекомендації не поширюються на відро. Таким чином, сирі файли (все за акту, 164 тис. актів) відносяться до відра, а датасет отримує рік у файлі, де він може.

    task text пише один markdown файл за акт з HTML. Список, які говорять 39,110 актів, мають HTML (все в Dziennik Ustaw, нараховані на 2026-10-13), в папках року кожен, тому датасет залишається всередині цих рекомендацій. Батьки PDF прийшли в фазу 12: з task text -- --pdf майже кожен акт отримує markdown файл, близько 164 тис. файлів, а тексти слід запакувати рік у файлі: Q16 of devlog просить його перед тим, як вони підштовхуються.

    Що було перевірено¶

    plan Працював проти реальних даних і відро. push і pull не працюють проти Hugging Face: їх порівняння покривається тестами, а завантаження та завантаження дзвінків не виконуються. Про нас push спочатку на невеликий каталог.
