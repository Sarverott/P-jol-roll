## 3. The holes

- **Reading is missing from every terminal way.** The launcher, the REPL,
  task and the CLI can gather everything and read nothing: no way to list
  the acts of a year or read a text without the api and a browser.
- **The launcher speaks in Taskfiles.** Its groups are the Taskfiles
  (`project`, `src`, `husky`...), not what a person wants; every task asks
  "arguments after --" with no word on what they may be. That is why its
  help does not help (the owner: "hard to use").
- **Half of the dataset is shown nowhere.** The work of Sejm, SAOS, the
  lists of the source, statistics: gathered, kept, never shown.
- **MCP reads less than the api**: no search, no map.
- **Writing functions** are offered only by terminals. Whether a local host
  (the desktop, an api on 127.0.0.1) may start them is Q19; until then the
  viewer shows them disabled, as the owner asked for the space.
- **Every way declares its functions on its own**: tasks in Taskfiles, the
  usage of `main.ts`, the routes, the MCP tools, the screens. Nothing says
  which function is where, so holes are found only by reading this table.

## 4. One code for every way

One catalog in core, `src/core/catalog/`: every function once, with its
group (read, gather, process, share, project), its parameters (name, what it
is, kind, choices, default), whether it writes, the task that runs it and
the reading that answers it here. Every way takes it from there:

- the **launcher** shows the groups of the catalog, asks the parameters one
  by one with their defaults, runs reading functions in the terminal and the
  rest as their tasks; every Taskfile stays under "every task";
- the **REPL** knows every function as a command (`acts DU 2026`), `help
  <name>` says what it takes;
- **task** and the **CLI**: `task do -- <name> <parameters>`;
- the **api** lists the catalog at `/api/catalog`, with what this host may
  do; the **viewer** shows it as a tab, the writing functions disabled
  (Bulma's `disabled`) where the host may not;
- **this table** is written from the catalog (`docs/guides/functions.md`),
  so a hole shows itself.

Reading functions answer through `src/core/reading/library.ts` in every way,
as before; a writing function is always its task, so a terminal, a workflow
and (after Q19) a local host start the same code.
